# Автозагрузчик черновиков Дзена

## Что можно запустить сейчас

Эта версия сканирует master, разбирает материалы восьми каналов, создаёт локальное HTML-превью, сохраняет указания для иллюстраций и ведёт журнал SQLite. Работает на компьютере владельца без ИИ и ключей API. Создание черновиков ещё не подключено. Основной BAT выполняет диагностику, объясняет причину остановки и возвращает код 2. Подтверждение сохранения и полнота списков Студии требуют отдельной проверки в авторизованном редакторе.

## Установка на Windows

1. Нужны Git для Windows и Python 3.11 с Windows Python Launcher. Проверка в PowerShell — `git --version` и `py -3.11 --version`.
2. Получите модуль в папку проекта. В PowerShell выполните `git -C "C:\CLAUDE_Project\Дзен" pull --ff-only origin master` на локальной ветке master. При конфликте Git остановится. Сохраняйте имеющиеся локальные изменения.
3. В папке `C:\CLAUDE_Project\Дзен\Автозагрузчик` запустите **Установить_автозагрузчик.bat**. Он установит зависимости в отдельную среду и откроет Chromium. Войдите в Дзен сами и нажмите Enter в консоли для сохранения профиля. При запросе проверки пройдите её самостоятельно.
4. Запустите **Проверить_без_загрузки.bat**. Программа получит снимок GitHub в отдельный кеш, не переключая вашу ветку и не затрагивая файлы авторов. Ошибка сети после повторной попытки остановит запуск. Консоль останется открытой.
5. Откройте `%LOCALAPPDATA%\DzenDraftLoader\last-report.txt`. В отчёте перечислены номера, заголовки, причины проверки и найденные заглушки. Превью находится в `preview\<id канала>\<номер>.html`, промпты и ориентиры — в `images\<id канала>\<номер>.json`. Превью открывается и копируется как форматированный текст. Проверять результат вставки в самом Дзене предстоит на пилоте.

## Какие материалы попадают в отчёт

| Источник | Правило |
|---|---|
| Пять художественных каналов | Нумерованные готовые файлы в корне канала, включая отдельные главы 11-1 и 11-2. Вложенные архивы и копии не участвуют. |
| Изнанка эпох | В корне только Статья-NN_ГОТОВО-К-ВСТАВКЕ.md и ранние .txt. Нумерованные тесты с другим префиксом пропускаются. Из ранних файлов извлекаются приложение с промптами и его привязки к номерам фото. |
| Тётя Айгуль | Сквозные номера и путь берутся из ВЫКЛАДКА.md до первой неготовой строки. Стоп-лист, внеочередные файлы и выдаваемые копии не сканируются. Пустое «Вышло» означает неизвестный статус. |
| Digital Ivan | Путь, номер, заголовок и готовность сверяются со строкой таблицы в 00_НАЧНИ-ОТСЮДА.md. Указание на вычитку, ожидание ника и расхождение заголовков отображаются как причины проверки. |

Форматирование результата можно проверить на HTML. Если редактор Дзена потеряет таблицу или разделитель при вставке, проверка пилота должна это обнаружить. Markdown исходника сохраняется. Любой неизвестный формат требует проверки до включения записи.

## Настройки и журнал

Установщик один раз копирует config.example.json в `%LOCALAPPDATA%\DzenDraftLoader\config.json`. Новый канал с уже поддерживаемым форматом подключается строкой в массиве channels. Поля id и folder определяют постоянную идентичность канала и папку. name — отображаемое имя, source — stories, history, queue или marketing, profile — локальный профиль аккаунта. При смене отображаемого имени сохраните id.

Для второго аккаунта задайте другой profile в настройках, затем выполните в PowerShell из папки модуля:

```powershell
& "$env:LOCALAPPDATA\DzenDraftLoader\venv\Scripts\python.exe" main.py login --profile second
```

База publications.sqlite, технический журнал, браузерные профили и кеш лежат под %LOCALAPPDATA%\DzenDraftLoader. Для переноса журнала закройте программу и сделайте резервную копию базы. Потеря базы требует новой первоначальной сверки. Одновременный запуск блокируется на уровне SQLite.

## Первоначальная сверка и пилот

Диагностика оставляет архив на проверку, даже если колонка публикации пуста. В репозитории есть логика сопоставления полного списка Студии по каналу и заголовку, хранения постоянной пары «канал + номер», резервирования попытки до создания и блокировки повтора после сбоя. Эти операции покрыты тестами на имитации браузера. Предстоит связать их с реальными списками и редактором.

1. Проверить действующие условия Дзена для автоматического чтения списков и сохранения собственных черновиков. При разработке получить действующий текст с официальной страницы не удалось. [Условия сервиса](https://dzen.ru/legal/ru/termsofuse/).
2. В отдельном профиле открыть «Барскую волю». На стороне разработки проверить постоянный идентификатор канала, адреса и признаки окончания списков «Черновики», запланированных и опубликованных материалов. Зафиксировать реальные элементы создания статьи, поля, индикатор автосохранения, ссылку и статус черновика. Профили и cookies передавать не требуется.
3. Только после полной сверки провести согласованный пилот с рассказом № 57 «Свечницу лишили месячины», если его ещё нет. Обновить страницу и сравнить заголовок, все абзацы, форматирование, финальное обращение и статус. При требовании обложки остановиться и добавить изображение вручную в этот же черновик.
4. Проверить повторный запуск и восстановление после прерванной записи. Затем подключить остальные каналы и ежедневный режим. До этого запуск основного BAT не создаёт статей и не выполняет действий публикации.

## Тесты

Из папки модуля выполните:

```powershell
& "$env:LOCALAPPDATA\DzenDraftLoader\venv\Scripts\python.exe" -m unittest discover -s tests -v
```

Тесты читают фактические исходники из родительской папки. Для проверки отдельного снимка можно задать DZEN_TEST_SOURCE. Чтобы запустить диагностику этого снимка без обращения к GitHub, используйте `main.py check --snapshot ПУТЬ --state ВРЕМЕННАЯ_ПАПКА`. Используйте отдельную временную папку состояния для тестов.
